## [0.1.0] - 2026-10-07

First release.

A maintained, desktop-agnostic reimplementation of KDE's KAppFinder, which
was marked unmaintained and dropped from release. Like the original it is
catalog-driven rather than heuristic: it knows about programs that commonly
arrive without a menu entry, checks which are installed, and offers to create
entries only for the ones missing.

### Added
- **117 catalog templates** covering legacy X11 applications, terminal
  emulators, TUI system monitors, file managers, editors, multiplexers,
  audio and video tools, network and chat clients, development tools,
  document and image viewers, and terminal toys.
- **`scan`** — read-only report of catalogued applications that are installed
  but have no menu entry. The default command.
- **`install`** — create the missing entries. Interactive by default, with a
  numbered list and `all` / `none` / `1,3,5-7` selection; `--yes`,
  `--dry-run`, and `--force` for non-interactive use.
- **`create`** — create an entry for specific binaries, catalogued or not.
  Uncatalogued binaries get generated defaults.
- **`orphans`** — opt-in, read-only sweep of every `$PATH` binary with no menu
  entry. A heuristic noise filter hides coreutils, libraries, and build
  plumbing; `--no-filter` disables it and `--limit N` caps the listing, where
  `0` means no limit. The filter is never applied to catalogued programs.
- **`remove`** — delete entries generated by this tool, identified by the
  `X-KAppFinder-Generated` marker.
- **`catalog`** — print the active catalog, with `--missing` to show only
  templates whose binary is not installed.
- **User catalog overlay** at `$XDG_CONFIG_HOME/kappfinder-rs/catalog.toml`.
  An entry with the same `bin` replaces a built-in one outright, with no
  rebuild required.
- **Existing-entry detection** across all XDG application directories plus
  Flatpak and Snap exports. Matching is by `TryExec`, then the program parsed
  out of `Exec` — seeing through `env VAR=x`, `sh -c "…"`, `nohup`, `pkexec`,
  `systemd-run` and similar wrappers — then the desktop file stem.
- **`--ignore-nodisplay`** to treat `NoDisplay`/`Hidden` entries as missing,
  for packages that ship a deliberately hidden entry.
- **`--dir`** to write entries somewhere other than
  `$XDG_DATA_HOME/applications`, and **`--catalog`** to point at an alternate
  user catalog.

### Safety
- Existing files are never overwritten without `--force`.
- Writes go through a temporary file and an atomic rename, and the temporary
  file is cleaned up if the rename fails, so an interrupted run cannot leave
  a partial entry in an applications directory.
- `remove` only touches files carrying this tool's marker, inside the target
  directory or the user's own applications directory.
- Non-interactive stdin never auto-confirms; `--yes` is required.
- The default `SIGPIPE` disposition is restored at startup, so piping output
  into `head` or similar exits quietly instead of panicking.

### Verification
- 41 unit tests covering `Exec` tokenising and wrapper unwrapping, Desktop
  Entry escape/unescape round-tripping, selection-expression parsing,
  filename sanitising, catalog invariants, and consistency between the
  catalog and the orphan noise filter.
- CI runs rustfmt, clippy with `-D warnings`, the test suite, and
  `desktop-file-validate` over an entry rendered from every one of the 117
  templates, failing on any validator output including hints.

### Known limitations
- Linux and other Unix only.
- The `orphans` filter is heuristic and will have false positives and
  negatives. It is deliberately kept out of the catalog-driven path.
- Flatpak entries launch via `Exec=flatpak run <app-id>`, which resolves to
  the program `flatpak` rather than the application, so a Flatpak install
  does not suppress an entry for a native binary of the same name.
