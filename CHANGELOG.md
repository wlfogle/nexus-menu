# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Fixed
- **`orphans` hid applications whose name ends in `d`.** A bare `"d"` suffix
  rule intended to catch daemons also matched real applications, including
  the catalogued `xclipboard` and `xload`, plus `kicad` and `freecad`.
  Daemons are now enumerated by exact name instead. The over-broad bare
  `"config"` and `"stat"` suffix rules were removed for the same reason —
  their real targets (`ifconfig`, `netstat`) were already matched exactly.
- **Piping output into another command panicked.** The Rust runtime sets
  `SIGPIPE` to `SIG_IGN`, which turns a closed pipe into a write error and
  makes `println!` panic. `kappfinder-rs orphans | head` aborted with
  `failed printing to stdout: Broken pipe`. The default `SIGPIPE`
  disposition is now restored at startup.
- **`--limit 0` showed nothing instead of everything.** It now reads as
  "no limit", matching the obvious interpretation.
- **A failed rename could leave a `.desktop.tmp` file behind** in an
  applications directory. The partial file is now cleaned up on error.

### Changed
- `orphans` never applies the heuristic filter to a catalogued program. The
  catalog is the ground truth for "this is a real application", so the
  heuristic no longer gets a vote on those.

### Added
- Test asserting no catalogued application is classified as noise, which is
  what caught the `xclipboard`/`xload` regression.
- Regression tests for names ending in `d`, `config`, and `stat`, and for
  daemons still being filtered.

## [0.1.0] - 2026-10-07

Initial release.

### Added
- Catalog-driven discovery of installed applications with no menu entry,
  shipping 117 templates covering legacy X11 applications, terminal
  emulators, TUI system monitors, file managers, editors, multiplexers,
  audio/video tools, network and chat clients, development tools, document
  and image viewers, and terminal toys.
- `scan` — read-only report of catalogued applications that are installed
  but missing a menu entry. The default command.
- `install` — create the missing entries, interactively by default, with
  `--yes`, `--dry-run`, and `--force`.
- `create` — create an entry for specific binaries, catalogued or not;
  uncatalogued binaries get generated defaults.
- `orphans` — opt-in, read-only sweep of every `$PATH` binary with no menu
  entry, with a heuristic noise filter and `--no-filter` to disable it.
- `remove` — delete entries generated by this tool, identified by the
  `X-KAppFinder-Generated` marker.
- `catalog` — print the active catalog, with `--missing`.
- User catalog overlay at `$XDG_CONFIG_HOME/kappfinder-rs/catalog.toml`;
  an entry with the same `bin` replaces a built-in one.
- Existing-entry detection across all XDG application directories plus
  Flatpak and Snap exports, matching on `TryExec`, then the program parsed
  out of `Exec` (seeing through `env`, `sh -c`, `nohup`, `pkexec` and
  similar wrappers), then the desktop file stem.
- `--ignore-nodisplay` to treat `NoDisplay`/`Hidden` entries as missing.
- Atomic writes via temporary file plus rename; existing files are never
  overwritten without `--force`.
- CI running rustfmt, clippy with `-D warnings`, the test suite, and
  `desktop-file-validate` over an entry rendered from every catalog
  template, failing on any validator output including hints.
